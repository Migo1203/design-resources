# Duolingo｜角色识别与系统化表达

## 研究目的

研究轮廓探索、共同构形和学习场景中的角色任务，区分历史设计过程与现行规范。

这是对已有项目研究的归纳归档。原始讲解、完整截图与反馈历史保留在来源仓库，本库维护一份可检索主记录。以下事实／观察均注明继承范围；分析和建议不视为用户认可。

## 核心结论

1. 原研究已读2013年Reshaping Duo及2020年Building character，并看八张相关截图，早期文字入口已有后续补充。
2. 官方过程文章讨论角色服务学习陪伴和内容反馈；不能仅用“可爱”或社交热梗概括其任务。
3. 轮廓比较、构形示例与动作变化提示先定义稳定关系再扩展表达，而不是只换颜色。
4. 文章中的角色和产品动图是历史官方示例，不等于本轮操作过学习产品或取得2026完整标准。

## 案例证据与历史查看范围

原研究查看轮廓草图、转面、历史演变、角色群、构形动图不同帧及练习三阶段，附八图；未登录产品、未研究社交账号。官网旧规范入口当时跳文章目录。本轮只读历史记录。

## 设计分析

下表是对原记录的归纳；未取得的资料保持待补充，不用常识补造作者意图或完整系统。

| 维度 | 证据、分析与边界 |
| --- | --- |
| 角色定位与人格 | Duo与人类角色群服务语言学习任务，不能直接移植给个人求职内容。 |
| 视觉特征与识别 | 整体轮廓、眼部和共同形状关系需要跨姿态保持；历史探索不等于可任意换标准形象。 |
| 表情动作 | 动作来自反馈情境；观者是否读懂情绪仍需真实测试。 |
| 色彩和插画 | 共同规则可容纳角色差异；不要求Beedog照搬绿色、大眼或同样可爱程度。 |
| 应用与商业延展 | 研究证据为练习示例与官方文章，没有周边经营或销售验证。 |

## 学习价值与不照搬部分

先写角色在何处出现、帮助用户理解什么，再比较结构差异；保留少量关键状态，不复制角色、比例、配色与庞大角色群。
