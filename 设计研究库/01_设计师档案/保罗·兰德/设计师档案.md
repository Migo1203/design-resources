# 保罗·兰德（Paul Rand）

## 研究目的

研究标志怎样以少量结构建立识别、如何在实际使用中保持品质，以及趣味图形与正式标志为什么需要不同权限。IBM为深入案例，UPS、ABC做横向比较，并保留原研究的NeXT。

## 核心结论

1. **事实**：IBM八条标志基本设计1972年形成，品牌现行规范仍分别修正正形和反白版；不能把网格等同于机械平均（R3、R4）。
2. **事实**：UPS研究对象是1961—2003历史版，ABC按AGI记1962；日期和版本必须与作者贡献一起记录（R7—R10）。
3. **本人观点**：1988访谈反对没有业务理由的换标，并讨论识别积累、制作适用性；不是“简单就永远正确”（R11）。
4. **分析推断**：IBM保字母骨架、UPS连接包裹与盾形、ABC统一圆形结构；简化的对象不同，不能拿一种几何公式解决所有品牌。
5. **事实与建议**：IBM限制Rebus替代正式签署（R6）；可启发Migo与Beedog分工，但不能反过来改写已确认品牌关系。

## 02 设计理念

[独立设计理念研究](设计理念.md)。本人访谈给出商业适用性和识别积累的依据；本库把“保留识别骨架—组织记忆点—检查媒介—规定用法”归纳为学习步骤，明确不是作者公布的固定流程。《Thoughts on Design》等著作仅核实书目，未通读，不伪造章节观点。

## 04 设计特点

| 维度 | 观察与范围 |
| --- | --- |
| 字体 | IBM粗衬线骨架、ABC圆形小写、UPS紧凑名称、NeXT大小写组合回应不同识别任务；不是统一字库 |
| 色彩 | 已看ABC/IBM黑白、UPS档案棕色、NeXT多色；棕色重绘不作历史印刷标准 |
| 构图 | 少量强关系：重复横条、上下符号、圆内名称、倾斜立方体；不宣称原作者按统一公式生成 |
| 材质 | SVG和照片不等于接触印刷实物；纸张、油墨、车辆涂装未实测 |
| 品牌识别 | 保留可读核心，趣味不妨碍正式身份；需版本、保护空间和背景条件 |
| 形式与内容 | 图形可以暗示业务，也可只承担名称识别；不要求每个Logo讲完全部品牌故事 |
| 一致性 | 在具体约束中简化与检查适用性，跨客户无需共享条纹或圆形 |
