# 研究状态说明

状态写入每份研究的 YAML Front Matter，是唯一索引数据源。状态变更必须同步更新时间，在正文“研究记录”写日期、旧状态、新状态、依据与未完成项；禁止只为好看升级。

| 状态 | 含义 | 进入或退出依据 |
| --- | --- | --- |
| 待研究 | 已登记对象，尚未开始研究 | 写明研究目的、候选来源和计划，不把假设写成发现 |
| 研究中 | 正在取证与分析 | 已开始访问资料或查看作品，记录本轮范围 |
| 待补充 | 有初步结论，证据或分析尚有缺口 | 列出缺口、影响和下一步，不能以模板齐全当作完成 |
| 已完成 | 达到最低记录标准，来源及内容检查通过 | 记录检查人、日期、范围、来源与角色核验、看图范围，阻塞性缺口已解决 |
| 已应用验证 | 方法已在真实项目使用并记录结果 | 在“已完成”基础上，提供项目路径、版本、采用方法、实际结果与证据；结果可以不理想 |
| 已搁置 | 暂停研究，保留已有内容 | 写明原因及恢复条件 |

## 完成检查

- 元信息、3–8 个词典标签、研究目的、3–5 条核心结论齐全。
- 至少一个真实作品／应用；目标、表现、方法、学习价值与不照搬部分具体且有依据。
- 类型专属维度齐全；设计师至少两个作品、一个深入拆解，明确个人角色和团队边界。
- 每个重要事实有 A/B 来源或明确保留未核实；来源有原始链接、访问日期和可信度。
- 所有视觉分析都有实际查看范围；推断、建议不冒充事实。分析范围与完成范围一致。
- 记录内容检查，自动脚本通过只是一项检查，不等于上述条件全部通过。

“已完成”不等于 Migo 认可该审美，也不等于项目已经采用。“已应用验证”更不等于有商业转化成果；没有实际数据不能补写成果。

## 常见转移

待研究 → 研究中 → 待补充／已完成 → 已应用验证；任何状态都可在发现资料错误时退回研究中／待补充，保留修正原因。已搁置可恢复到研究中。YAML 日期使用 `YYYY-MM-DD`，本库首批建档日期为 2026-11-12，不倒填为历史访问日期。
