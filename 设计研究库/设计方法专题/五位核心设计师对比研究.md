# 五位核心设计师对比研究

版本：R02；日期：2026-11-13。本文是方法比较与Migo策略建议，不重复人物介绍，不输出Logo、角色或网站设计稿。

## 研究目的

回答三个实际问题：Migo怎样以作品与视觉建立专业认知；品牌角色怎样承载个人联系与情绪；网站与作品集怎样让这些信息被清楚阅读。将五位设计师的案例证据，转化为可解释、可比较、可验证的取舍依据，而不是合并五种风格。

与[第一批设计师研究总结](第一批设计师研究总结.md)的区别：旧稿保留首轮学习归纳；本稿专门完成十维方法比较、Migo五类用途、角色七类问题、三组设计原则和验证假设，并对照2026-11-12最新AC3记录。本文为本轮策略提炼主档，不复制各人的生平和全案。

## 核心结论

1. **跨案例分析**：五人可比较的是问题如何进入形式、识别如何保持、变化如何管理，不能归纳成“留白＋条纹＋网格＋复古徽章＋几何人物”的外观配方。
2. **Migo策略建议**：以“身份与贡献清楚、识别稳定、内容有层级、变化有依据”为共同原则。专业可信度由真实项目与判断支持，不由极简风格或角色造型单独证明。
3. **角色策略建议**：以现有AC3偏好为输入，先检验轮廓、视角一致性与观察／尝试动作；不重启五人风格拼接，也不将早期圆鼓脸、尖耳或某个头身比恢复成不可改规则。
4. **网站策略建议**：编辑式布局首先组织阅读与作品证据；角色和动效承担具体叙事／反馈职责。网站只接入品牌项目已确认且适用的资产。
5. **验证边界**：本轮形成候选原则与测试设计，尚未进行方案对照或用户测试。人物档案仍标“待补充”，只引用其中有依据的范围；不自动升级研究状态或认定用户认可。

## 01 方法定义、输入与证据范围

### 比较的单位

方法指“面对一个约束，怎样作出选择并检查结果”；风格指选择所呈现的外观特征。两者不能互相替代。例如，IBM的正反校正可以启发Migo检查标志明暗关系，但不要求Migo使用横条；Nike角色的姿态家族可以启发动作检查，但不要求角色成为同款几何人形。

比较采用“问题 → 可核实事实／既有图像观察 → 方法推断 → Migo适用性 → 失败条件”的链条。下文矩阵是本库的比较分析；事实以E编号案例及来源表为依据，不冒充设计师本人公布的统一流程。

### 比较后的取舍

最值得共同借鉴的是：让形式有任务依据、以清楚核心容纳变化、把真实应用和维护纳入判断。需要分别调用的是：标志的光学问题、角色的情绪问题、编辑内容的阅读问题。三者可以共享原则，但验收证据不同。

五位都不能单独提供完整的Beedog角色规范或完整的网站UX依据。角色仍需原创结构与实际动作测试；网站仍需现有线框、内容、键盘与移动体验检查。已有成熟品牌的知名度不能当Migo的新品牌起点。

### AC3实际查看与DNA候选

本轮实际打开AIGC基线中的`AC3_简化基础形象_概念图_V02.png`整图（1536×1024）。可见三个概念角度、双足、每侧宽大的耳翼轮廓、深色头胸分区、浅色面中线与口鼻、蜜色眉斑和四肢色块；侧面仍有透视。这里的“可见”是图像观察，不是用户已确认，也不补作精确比例／色值测量。

**分析推断**：耳翼扩展与紧凑体块是值得先检验的外部关系，面部分区与眼神是内部辨识候选。毛尖、耳内线条和小色块能否简化，应看对识别和表情的实际影响；不能因为Draplin强轮廓就全加厚线，或因为Yukai几何人物就删去犬类面部。

建议验证时分别保存：完整彩色基准、同轮廓单色观察、只简化局部的对照、静态动作。单色剪影只能检验外轮廓，不能据此证明眼神／面部分区没有价值。后续同类比较需使用有来源的真实角色，先写出可见相似与差异，不把主观“看起来不像”当原创或法律结论。

V07眼区比较可纳入H02／H03的后续检查：同一基础脸分别看原版、直接蜂眼和面具是否保留视线、眼睑及口鼻的表达空间，是否抢过耳翼识别。已有二维对照不算表情、摘戴或小尺寸测试通过，也不因此新增动画制作。

## 05 Migo网站视觉与编辑式布局原则

### 候选内容秩序

首页先让访客理解Migo身份及作品入口；作品列表帮助挑选；NED详情继续沿用已确认骨架“概述 → 本人工作与AI协作 → 设计判断 → 四段完整成果 → 简短复盘”。关于补充背景，联系提供真实渠道，404能返回有效页面。本稿不改变六类页面范围，也不把研究阅读顺序当正式导航顺序。

编辑式布局建议区分三类密度：总览提供范围，判断段把结论贴近图像证据，完整成果保留可读细节与查看入口。同一页可有通栏图、图文并列和单列正文；选择依据是内容任务，不是机械排满同一种网格。旧审阅稿画板外灰区也不是最终网站必须保留的视觉样式。

### 网站视觉设计原则（W01—W05）

| 原则 | 建议落实方式 | 验收问题 |
| --- | --- | --- |
| W01 作品与贡献是阅读主体 | 项目名、摘要、本人角色、AI协作与成果入口有明确层级；不用角色代替项目封面信息 | 不读长文能否知道项目任务？进一步阅读能否分清谁做了什么？ |
| W02 网格服务内容 | 对齐与段距形成秩序，长标题、长图和不同项目类型允许合适变化 | NED与未来品牌IP项目填入后是否都自然？图注是否跟着证据而非远离图片？ |
| W03 中英文是一套信息系统 | 对照真实中英文标题、数字、专业词与长段落；检查字重、行距、换行、缺字和授权 | 语言切换是否保留对应内容和项目身份？未审阅译文有无被当终稿？ |
| W04 角色和动效有任务 | 欢迎语、情境提示或反馈只有明确用途才加入；不遮作品、按钮和正文 | 少角色版本是否仍完整？动态能否跳过／减少，静态降级能否理解？ |
| W05 品牌来源和网页实现分开 | Project A确认资产，网站记录版本、许可与使用处；网页适配不反向改品牌源文件 | 临时字体、色彩、角色是否仍标Pending？宽屏、手机与键盘阅读是否都可用？ |

字体候选和色板测试可以继续，但本稿不指定最终字体、RGB或角色露出比例。几何感可来自结构与对齐，不必采用相同无衬线；活泼可以来自动作与内容，不必全页高饱和。作品自身色彩与网站界面色彩分层管理。

本轮形成的设计策略是：**让身份和作品有清楚秩序，让角色用稳定识别与具体行为承载好奇，再由真实应用决定哪些规则值得保留。** 这是内部工作建议，不是新口号或已获认可的视觉路线。

可迁移的是提问、取舍、光学校正、信息层级、固定／变化与协作方法；不能迁移的是设计师个人名气、成熟品牌认知、客户事实、图像资产和未经测试的成效。角色命名与细节服从品牌项目最新记录，网站不能反向定品牌标准。
