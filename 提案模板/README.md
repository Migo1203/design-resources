# 可视化商业提案模板

这是可以离线打开的中文 HTML 模板，帮助比较同一 Brief 下三个有实质差异的商业 KV 创意方向。默认数据只是**结构演示**，没有真实产品 Brief、用户选定的参考图或完成的看图分析，不能作为已完成提案交付。

[打开 HTML 模板](index.html) · [查看 PDF 结构预览](提案结构预览.pdf) · [商业提案流程](../商业提案流程/README.md) · [审美参考包](../审美参考包/README.md)

PDF 是默认空模板的结构预览，包含演示色板和线框，没有真实参考作品或用户评审。填写实际项目后应重新导出，不沿用此预览作为正式提案。

## 使用

1. 将本目录的 `index.html`、`proposal-data.js`、`proposal.js` 和 `README.md` 一起复制到具体项目的提案版本目录，保留文件间的相对位置。复制到更深层目录后，核对说明文件指向仓库其他目录的相对链接；旧 PDF 仅供结构参考，正式提案需重新导出。
2. 编辑 `proposal-data.js`：先填写同一份 Brief 的事实、假设和限制，再重写三个方向的概念、理由、机制与结构。演示中的“关系与尺度 / 结构与证据 / 隐喻与识别”只是三种结构示意，不是任何产品都适用的固定答案。
3. 给每个方向选择真实参考图。优先引用审美参考包中用户已明确认可的案例；少量否决案例用于解释边界，不当作正面风格依据。`references[].image` 填相对于 HTML 文件的本地图片路径，`source` 填来源网页链接，`selectionStatus` 记录“待确认 / 认可 / 不喜欢”等用户态度，`viewStatus` 独立记录“未查看 / 已查看部分 / 已查看”。可填写 `viewedAt` 和 `viewScope`，保留查看日期与图号或范围；不要把用户态度与看图状态混成一个结论。
4. AI 必须实际打开图片并查看后，再填写 `observation`（摄影、字体、构图、材质等可核对的观察）、`commercialRole`（对商业目标的作用）、`borrow`（借鉴机制与不照搬的资产）。网页能载入图片不等于 AI 已查看；找不到或打不开时保持“未查看”，不编造细节。
5. 用浏览器打开 `index.html`。没有网络、服务或构建依赖；不自动请求外部图片、字体。它会显示 Brief、方向比较、参考图、HEX 色板、字体样张、线框、系列延展、缺口和逐方向评审输入。GitHub 文件页显示源码，需把目录文件下载到同一位置后用浏览器打开。
6. 让用户直接比较可观看方案，记录选中、修改、否决或暂缓的理由。方向选定后才进入必要的提示词、补拍和 PS 制作。

## 编辑数据

- `projectId / version / status`：项目、提案版本和真实进度。正式提案须去掉结构演示内容，保留未核实项。
- `brief`：产品、问题、受众、主信息、渠道、已确认事实、假设与限制。同一次方向比较不悄悄更换 Brief。
- `directions`：三个方向的概念、适配理由、创意机制、摄影、材质、字体、色板、参考拆解、系列延展和素材缺口。方向数量按本模板为三；同一机制换颜色不能充数。
- `colors`：六位 HEX 色值和每种颜色的作用；默认色板仅为演示，不代表用户选择。
- `layout`：`relationship`、`evidence`、`metaphor` 对应三种内置 SVG 线框。它们只是结构示意，没有 AI 生图，也不代表真实产品形态。实际任务应按创意修改 `proposal.js` 中的线框绘制或补充真实线框，不能机械沿用。
- `references`：每项包含图片本地相对路径、来源、用户态度 `selectionStatus`、看图状态 `viewStatus`、可选日期 `viewedAt` 与图号/范围 `viewScope`、观察、商业作用和借鉴边界。页面图片的加载状态单独显示；加载成功或失败都不会修改用户态度与历史看图记录。仅有图片链接不足以声称已完成分析。

## 字体样张

默认样张使用当前设备的系统字体，页面显示 CSS 候选栈和“系统示意”状态，**不声称精确字体已安装或选定**。为真实提案确认字体时，将有权使用的字体文件放到项目目录：

```js
typography: {
  family: "system-ui, sans-serif", // 加载失败时的回退栈
  role: "填写字体性格、层级和它对概念的作用",
  file: "assets/fonts/自己的字体.woff2", // 相对于 index.html
  fileFamily: "ProposalLocalFontA" // 自定义唯一家族名
}
```

浏览器会通过 `FontFace` 加载并显示成功或失败状态。成功只说明文件已加载；中文缺字仍可能回退，需核对实际样张与许可。字体文件不得因本模板而被擅自公开或提交到仓库。未确认字体时保留系统示意。

## 评审与 PDF

每个方向初始为“待评审”。选中、否决、修改或暂缓后，必须写具体原因才可导出 JSON；也可如实导出尚未评审的状态。页面不使用本地存储，不自动保存，刷新或关闭会清除未导出的表单内容。

点击“导出本轮评审 JSON”，确认浏览器完成下载，再将文件放入具体项目的评审目录（例如 `评审记录/2026-10-27-v01.json`），并在[选择与修订记录](../商业提案流程/选择与修订记录.md)摘要实际决定、理由、修订与验证结果。导出不会自动写入仓库、改参考认可状态或更新 Skill。

点击“打印 / 另存 PDF”，使用浏览器的“另存为 PDF”；A4 打印样式会将每个方向另起一页、保留色板并尽量避免卡片截断。打印前展开并检查全部内容，确认图片已载入、中文字体可读、长内容分页合理。PDF 是页面快照，JSON 与源数据仍需一起保存。

## 交付前检查

- 三个方向在机制、产品关系或画面结构上有实质区别，且都回应同一 Brief。
- 真实参考图片可见、来源与状态完整，AI 已实际查看才写拆解；图片丢失会显示缺图提示。
- 摄影、字体、构图和材质都有商业作用说明，色板和样张与方向对应。
- 线框说明信息、产品、图形与留白关系，不冒充最终效果或已核实的产品结构。
- 未确认宣称、素材、字体与实现缺口明确；用户能根据页面选择，不依赖 AI 直接生图。
- 选择理由和修订结果被真实记录；方法经验证后再讨论写入 Skill。
